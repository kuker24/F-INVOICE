# PRODUCT REQUIREMENTS DOCUMENT

## F-INVOICE

**Versi:** 1.0 MVP
**Jenis aplikasi:** Private Invoice Management System
**Platform awal:** Web responsif
**Pemilik sistem:** Developer/Owner
**Target pengguna:** Developer, Admin internal, dan pelanggan aplikasi
**Status:** Siap dikembangkan

---

# 1. Ringkasan Produk

F-INVOICE adalah aplikasi web private untuk mengelola invoice penjualan project, biaya maintenance, hosting, langganan aplikasi, dan pembayaran pelanggan.

Aplikasi hanya digunakan oleh:

1. **Developer**

   * Pemilik aplikasi.
   * Memiliki kendali penuh terhadap seluruh sistem.

2. **Admin**

   * Membantu mengelola pelanggan, invoice, langganan, dan pembayaran.
   * Tidak dapat mengubah pengaturan penting sistem.

3. **User**

   * Pelanggan yang membeli project atau berlangganan aplikasi.
   * Hanya dapat melihat data miliknya sendiri.

F-INVOICE bukan marketplace dan bukan SaaS publik. Registrasi umum tidak tersedia. Semua akun dibuat atau diundang oleh Developer.

---

# 2. Tujuan Produk

F-INVOICE harus memungkinkan Developer untuk:

* Menyimpan data pelanggan.
* Menyimpan daftar layanan dan produk.
* Membuat invoice secara cepat.
* Membuat invoice langganan berkala.
* Menghasilkan invoice dalam format PDF.
* Membagikan invoice kepada pelanggan.
* Memantau invoice yang belum dibayar.
* Mencatat pembayaran pelanggan.
* Mengelola akun Admin dan User.
* Melihat histori aktivitas sistem.
* Mengatur identitas bisnis dan rekening pembayaran.

# 5. Teknologi yang Digunakan

## 5.1 Frontend

* Next.js App Router.
* TypeScript.
* Tailwind CSS.
* shadcn/ui.
* React Hook Form.
* Zod.
* TanStack Table jika dibutuhkan.
* Recharts untuk grafik dashboard.
* Lucide Icons.
* Sonner untuk toast notification.

## 5.2 Backend

* Next.js Server Actions atau Route Handlers.
* Supabase PostgreSQL.
* Supabase Authentication.
* Supabase Storage.
* Supabase Row Level Security.
* Vercel untuk deployment.
* Vercel Cron untuk proses invoice langganan.
* React PDF atau HTML-to-PDF untuk invoice PDF.

## 5.3 Prinsip Arsitektur

* Frontend tidak boleh langsung melakukan operasi sensitif.
* Perhitungan invoice dilakukan ulang di server.
* Service role Supabase hanya digunakan di server.
* Seluruh data utama memiliki `owner_id`.
* Seluruh request harus melalui validasi Zod.
* Hak akses harus diperiksa di frontend, backend, dan database.

Developer merupakan pemilik sistem dan memiliki full control.

Developer dapat:

* Logo F-INVOICE.

* Tombol “Masuk”.

## Tombol

### Masuk

Fungsi:

* Memvalidasi email dan password.
* Mengirim permintaan login.
* Mengarahkan pengguna berdasarkan role.

Redirect:

* Developer → `/dashboard`
* Admin → `/dashboard`
* User → `/portal`

Mengarahkan ke:

```text
/forgot-password
```

## Validasi

* Email wajib diisi.
* Email harus valid.
* Password minimal 8 karakter.
* Tampilkan pesan jika akun tidak aktif.
* Tampilkan pesan jika email atau password salah.
* Gunakan loading state saat proses login.
* Tombol tidak dapat diklik berulang kali saat loading.

# 11.5 Nomor Invoice

Nomor invoice dibuat melalui transaksi database agar tidak terjadi duplikasi.

Format default:

```text
FINV-{YEAR}-{SEQUENCE}
```

Contoh:

```text
FINV-2026-0001
```

Proses:

1. Mulai database transaction.
2. Ambil sequence tahun berjalan dengan row lock.
3. Tambahkan sequence.
4. Buat nomor invoice.
5. Simpan invoice.
6. Commit transaction.

Nomor invoice yang sudah digunakan tidak boleh digunakan ulang.

---

# 11.6 Perhitungan Invoice

Seluruh perhitungan dilakukan server-side.

## Perhitungan Item

```text
gross = quantity × unit_price
after_discount = gross - discount_amount
tax_amount = after_discount × tax_rate
line_total = after_discount + tax_amount
```

## Perhitungan Invoice

```text
subtotal = total seluruh item sebelum diskon invoice
total_amount = subtotal - discount_amount + tax_amount + additional_fee
amount_paid = total pembayaran VERIFIED
balance_due = total_amount - amount_paid
```

Gunakan integer untuk nilai rupiah.

Contoh:

```text
Rp1.500.000 disimpan sebagai 1500000
```

---

# 11.7 Transisi Status Invoice

Transisi yang diizinkan:

```text
DRAFT → SENT
DRAFT → CANCELLED

SENT → VIEWED
SENT → PARTIALLY_PAID
SENT → PAID
SENT → OVERDUE
SENT → CANCELLED

VIEWED → PARTIALLY_PAID
VIEWED → PAID
VIEWED → OVERDUE
VIEWED → CANCELLED

PARTIALLY_PAID → PAID
PARTIALLY_PAID → OVERDUE
PARTIALLY_PAID → CANCELLED

OVERDUE → PARTIALLY_PAID
OVERDUE → PAID
OVERDUE → CANCELLED
```

Invoice `PAID` tidak dapat dibatalkan tanpa proses pembatalan pembayaran oleh Developer.

---

# 11.8 Overdue Invoice

Cron berjalan minimal satu kali sehari.

Proses:

1. Cari invoice yang belum lunas.
2. Periksa `due_date`.
3. Jika tanggal sekarang melewati jatuh tempo:

   * Ubah status menjadi `OVERDUE`.
   * Buat notifikasi.
   * Buat activity log.

Status `DRAFT`, `PAID`, dan `CANCELLED` tidak boleh berubah menjadi overdue.

---

# 11.9 Generate Invoice Langganan

Cron endpoint:

```text
/api/cron/subscriptions
```

Endpoint hanya dapat dipanggil menggunakan secret Vercel Cron.

Proses:

1. Cari subscription `ACTIVE`.
2. Periksa `auto_generate_invoice = true`.
3. Periksa `next_invoice_date <= current_date`.
4. Pastikan belum ada invoice pada periode yang sama.
5. Buat invoice `DRAFT`.
6. Buat invoice item.
7. Perbarui `next_invoice_date`.
8. Buat notifikasi.
9. Buat activity log.

Proses wajib idempotent agar invoice tidak dibuat ganda.

* Developer dan Admin dapat mengedit pelanggan.
* User tidak dapat melihat pelanggan lain.

* Developer dan Admin dapat membuat invoice.

* Nomor invoice unik.
* Invoice dapat disimpan sebagai Draft.

* Developer dan Admin dapat membuat langganan.

## Role

* Developer memiliki seluruh permission.
* Admin tidak dapat mengubah pengaturan sensitif.
* User hanya dapat mengakses data miliknya.
* Backend menolak akses meskipun URL dimasukkan manual.

## Audit

* Perubahan penting tercatat.
* Activity log tidak dapat diedit.
* Developer dapat melihat seluruh log.

# 25. RINGKASAN PRODUK FINAL

F-INVOICE versi MVP merupakan aplikasi invoice private dengan struktur:

```text
Developer
└── Full control seluruh sistem

Admin
└── Operasional pelanggan, invoice, langganan, dan pembayaran

User
└── Portal pelanggan untuk melihat dan membayar tagihan
```

Fokus utama MVP:

```text
Pelanggan
→ Invoice
→ PDF
→ Pembayaran
→ Langganan
→ Portal User
```

Sistem harus dibuat sederhana, aman, mudah digunakan, dan dapat dikembangkan secara bertahap tanpa membangun fitur SaaS publik yang belum dibutuhkan.
